# Security policy

Report suspected vulnerabilities privately through GitHub's **Security → Report a vulnerability** feature when enabled, or contact the repository maintainer privately through GitHub. Do not open a public issue containing an exploit, a token, a contact record, or other personal information.

Include affected versions, impact, and steps to reproduce using synthetic accounts and data only. Do not access or test the maintainer's live deployment without permission. The maintainer aims to acknowledge reports when available; no response time is guaranteed.

The supported code is the latest main branch. Self-hosters are responsible for applying updates, configuring authentication, restricting production access, and protecting their databases. See [the deployment checklist](docs/open-source-readiness.md).
